# QasidRelay 0.1.8-rc2 — release candidate validation

This is an **unreleased, non-production QA candidate** building on
[the 0.1.8-rc1 checklist](0.1.8-rc1-qa.md). Retain all previous required
physical-SIM checks and security boundaries.

## Changes since rc1

- In-process service liveness prevents Android process death from leaving
  a false healthy/running dashboard state when the operator reopens the app.
- The sender UI cannot downgrade an already received terminal SMS callback to
  queued/skipped when the callback is exceptionally fast.
- Additional Android emulator tests cover these cases.
- New versionCode **10**, versionName **0.1.8-rc2**.

## Release process

1. Review the PR and verify static, Android build/unit tests, and all emulator
   instrumentation checks at the exact head commit.
2. Download the **signed** APK artifact from that CI run. Verify APK signature,
   SHA-256 digest, and install/update behavior before field tests.
3. On an authorized Android phone with a controlled SIM, confirm phone-
   initiated HTTPS/HMAC polling, one transactional test SMS, the Android
   sent callback, status acknowledgement, pending-report recovery, and
   foreground/manual restart after reboot, process death and update.
4. Verify a real failure (e.g., temporary offline network) and confirm no
   raw recipient, OTP, message body, device key or signed headers appear in
   status/clipboard or support captures.
5. Record real device manufacturer, Android version, model, SIM setup, APK
   signing continuity and observed behavior in the release checklist.
6. Only then consider publishing a **prerelease**. A stable release needs
   further field validation.
